#############################################################################
# 1. WHAT THE SYSTEM IS
#############################################################################
- Custom Potree viewer for inspecting laser-scan point clouds. Features built on
  top of stock Potree: mark/measure/member-sketch tools, constraint planes &
  axes, fit-plane, DXF export, save/load session, undo/redo, snap-to-endpoint,
  elevation/heat-map (some clients), clip box + cut-out/exclusion volumes,
  station panorama pins + modal, multi-scan (load several clouds, toggle in a
  right-hand "Scans" panel), saved views, and a Firebase login portal (BDA).
- Each CLIENT is a folder under site/clients/. The active development sandboxes
  are Dev/ and Dev2/. Production clients: August, BDA, Conterra, Fida
  Restoration, HRI, MurrayFranks, Pomerleau, Solar Restoration, WJ Properties.
- A viewer instance is opened as:  <client>/viewer.html?p=<project_id>
  where project_id is a key in that client's projects.js.

# 3. ENVIRONMENT / TOOLS (Windows)
#############################################################################

#############################################################################
# 4. DATA PIPELINE: raw scan -> served octree
#############################################################################
A) Inspect the LAS first (python + laspy): point count, RGB range (16-bit:
   0..65280 = 8-bit x256, so divide by 256 / >>8), native nearest-neighbor
   spacing, and bounds (to confirm a new HD/sub-scan aligns with the main scan).

B) Convert with PotreeConverter — RUN FROM POWERSHELL, from the converter dir,
   input as a POSITIONAL arg, use --attributes (not -a):
     cd 'C:\PotreeTools\PotreeConverter_1.7_windows_x64'
     .\PotreeConverter.exe "C:\...\<scan>.las" -o "C:\...\pointclouds\<id>" `
        -s 0.05 --scale 0.001 --attributes RGB INTENSITY --material RGB --overwrite
   - `-s` = ROOT spacing in metres (coarsest LOD; halves each deeper level).
     Conversion is LOSSLESS (octree cloud.js "points" == LAS point count — verify).
     Use FINER spacing to resolve fine features (cm GPR marks): 0.05 for big
     slabs (~30M pts), 0.01 for dense HD strips (~mm spacing). Default auto-
     spacing (~0.2-0.4) is too coarse for reading marks.
   - Convert to a *_v2 / temp dir, verify cloud.js, then swap folders; keep the
     old one in a _stale/ dir until confirmed, then delete.

C) (Optional but important for scanner color noise) COLOR-AWARE DESPECKLE.
   Symptom: scan looks crystal-clear in CloudCompare but speckled/washed-out in
   our viewer, white scan-line speckle burying colored (GPR) marks. CAUSE: the
   SOURCE colorization is noisy (~18% near-white points scattered through
   concrete); CloudCompare hides it by drawing ALL points dense, Potree shows a
   sparse LOD subset so each noisy point shows. The PotreeConverter does NOT
   average color — do not chase that. FIX = python despeckle that replaces only
   salt-and-pepper outliers while PROTECTING mark colours:
     - per point: 3D KNN median (k=12, scipy cKDTree, chunked query workers=-1)
     - replace only if dev=sum|RGB-median|>~85 AND not a protected colour
     - protect mask: (B>G+4) | (G>R+6) | (max-min>70)  [blue/green/saturated]
     - write back as 16-bit (value*256) so PotreeConverter handles it identically
   A PLAIN median (no protection) ERASES thin marks (they look like outliers vs
   white neighbours) and posterizes into blotches — that was a wrong turn.
   Helper scripts live (gitignored) at:
     site/clients/HRI/40 Larch 1/_despeckle.py  and  _inspect.py

D) Density when zoomed: native spacing may be ~1cm but the viewer can look
   2-3cm because of LOD throttling (NOT data loss). Levers in viewer.html:
   viewer.setPointBudget(...) and viewer.setMinNodeSize(20) (Potree default 30;
   lower = denser/deeper nodes load). The +/- keys are bound to point BUDGET,
   not size. When zoomed into a fully-loaded region you already see every point
   (== CloudCompare); remaining "CC is crisper" gap is render STYLE (point size
   slider / shape / EDL), and CC just draws all points always (no LOD).

#############################################################################
# 6. PUSHING TO GITHUB (large data — MUST chunk)  *critical recipe*
#############################################################################
Repo: Enable-inc-git/enable_point_cloud_viewer over HTTPS. Netlify deploys
`main`. Convention here is to commit/push straight to main (that is the deploy).
Two real failure modes and their fixes:
  1. A single ~300MB push RESETS ("curl 55 Send failure: Connection was reset").
     FIX: split into multiple commits of ~80MB (48-110MB proven safe) and
     `git push` AFTER EACH — each push only uploads that commit's new objects.
  2. `git add file1 ... file400` -> "Argument list too long" (Git-Bash ARG_MAX),
     and it SILENTLY commits nothing. FIX: `git add` ONE file per call in a loop.
Working loop (bash), tally bytes, commit+push every ~80MB, verify each push:
  - first commit = code + manifests (cloud.js, sources.json, stations.json,
    projects.js, .gitignore) -> push (validates auth/connectivity)
  - then loop over `git ls-files -z --others --exclude-standard "<Project path>"`
    adding one file each, commit+push at ~80MB, final commit for remainder.
  - AFTER EACH PUSH verify `git rev-parse HEAD == git rev-parse origin/main`
    (a reset push can still exit 0 in a pipe — exit code is NOT proof).
  - End state: `git ls-files --others --exclude-standard "<path>" | wc -l` == 0.
A known-good script template was used for HRI 40 Larch 1 and 30 Weston Rd; see
the loop in §6 above — reproduce it as a .sh in the OS temp dir and run it in
the background (pushes can take minutes).
GITIGNORE already excludes: *.las, *.e57, *.scan, /potree/, each client's
panorama staging (images/ or HighResolution/), and HRI _*.py / _stale/.
NEVER commit: raw scans, *_project.bin scratch (can be many GB), tool checkouts.

#############################################################################
# 9. SELECTED GOTCHAS
#############################################################################
- viewer.html is huge; custom JS is inline in one IIFE. Separate THREE.Scenes
  for markers/constraints/members/labels, rendered in render.pass.perspective_overlay.
- Potree's scene.view (yaw/pitch/position/radius) drives the camera every frame;
  setting camera transform directly gets overwritten — use scene.view.*.
- Right-click is custom-intercepted to always pan (even during measurement).
- Persistent clip box is grabbable by its WIREFRAME EDGE only (interior orbits).
  A manual capture-phase OBB hit-test selects the OTHER managed boxes (elevation/
  cut-out/exclusion) whose fill raycast is off; it uses an INFINITE ray, so it
  must DEFER to Potree whenever Potree hovered ANY scene volume, else it hijacks
  clip-box-edge clicks and they go unresponsive. (Keep edge-only; do NOT make the
  interior clickable — that was explicitly rejected.)
- Production URL (Netlify) is case-insensitive and works with/without ".html".
